# Percentages

> [!abstract] 🔴 HIGH · ≈10% of arithmetic questions · Target accuracy **90%+** · Budget **1.5 days**
> Foundation for P&L, interest and DI. The **x/(100+x) trap** appears repeatedly — drill it until automatic.

## Core formulas

| Concept | Formula | Quick example / shortcut |
|---|---|---|
| % change | (New − Old)/Old × 100 | Base = **old** value |
| A is x% more than B → B is less than A by | x/(100+x) × 100 % | 25% more ↔ 20% less |
| A is x% less than B → B is more than A by | x/(100−x) × 100 % | 20% less ↔ 25% more |
| Successive changes a, b | a + b + ab/100 | +10, −20 → −12% |
| Price up r% → cut consumption by | r/(100+r) × 100 % | 50% up → 33⅓% |
| Population growth | P(1 + r/100)ⁿ | 3 yrs at 5% → ×1.157625 |
| Fail/pass (sets) | Pass = 100 − (A + B − Both) | 35 + 25 − 10 = 50 → 50% pass |

## Visual

```text
 100 ──+25%──► 125 ──−20%──► 100      (net 0)
 100 ──+10%──► 110 ──−20%──►  88      (net −12%)
 Up and down % NEVER cancel unless 1/(1+x) is used
```

## Exam Trap ⚠️

> [!warning] Exam Trap ⚠️
> - **x/(100+x) trap**: if A is 20% less than B, B is **25%** more than A — not 20%.
> - Successive % changes multiply; they never just add or cancel.
> - % change base is always the **starting** value.
> - 'Increase by x%' → ×(1+x/100); 'is x% of' → ×x/100. Don't swap them.
